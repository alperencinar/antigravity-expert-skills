# URP Curved World Shaders & Lighting Optimization: Technical Architecture & Implementation Guide

## Executive Summary

Building a performant curved-world rendering system in Unity's Universal Render Pipeline (URP) requires tight synchronization across graphics math, shader passes, CPU culling pipelines, and light classification models. This document provides a complete technical synthesis and reference implementation covering:

1. **2-Axis Quadratic Curvature HLSL Mathematics**: Vertex displacement derivation, normal recalculation via analytical partial derivatives, and CBUFFER layout for full SRP Batcher compatibility.
2. **ForwardLit & ShadowCaster Pass Parity**: Eliminating shadow detachment and artifacts by maintaining exact vertex transformation parity between main rendering and shadow map generation passes.
3. **CPU AABB Frustum Culling Expansion**: Mathematical bound estimation and C# runtime automation for `Mesh.bounds` and `Renderer.localBounds` to eliminate frustum culling popping.
4. **Vehicle Headlights & URP Lighting Architecture**: Deep evaluation of Forward+ vs Forward (Per-Object) vs Deferred paths, spotlight cookies, additional light shadow performance, and SRP batching invariants.

## 1. Mathematical Derivation of 2-Axis Quadratic Curvature HLSL Vertex Displacement

### 1.1 Quadratic Curvature Formulation

Curved world shaders bend world-space geometry dynamically in the vertex stage based on the distance from a reference anchor (typically the active camera or world origin). A 2-axis quadratic curvature model applies independent bending forces along both the horizontal ($X$) and longitudinal ($Z$) axes.

Let $P_{ws} = (x_{ws}, y_{ws}, z_{ws})^T$ be the unmodified world-space vertex position, and $C_{ws} = (x_c, y_c, z_c)^T$ be the reference anchor position in world space.

Define the relative distance vector $\mathbf{D} = (d_x, d_y, d_z)^T$:
$$d_x = x_{ws} - x_c$$
$$d_z = z_{ws} - z_c$$

The 2-axis quadratic vertical displacement $\Delta y$ is defined as:
$$\Delta y = -\left( K_z \cdot d_z^2 + K_x \cdot d_x^2 \right)$$

where:
- $K_z$ is the longitudinal curvature coefficient (bends the world down as distance along $Z$ increases).
- $K_x$ is the horizontal/lateral curvature coefficient (bends the world down as distance along $X$ increases).

The displaced world position $P'_{ws} = (x'_{ws}, y'_{ws}, z'_{ws})^T$ is:
$$P'_{ws} = \begin{pmatrix} x_{ws} \\ y_{ws} - (K_z d_z^2 + K_x d_x^2) \\ z_{ws} \end{pmatrix}$$

```
                   Unbent World (Flat)
       +-----------------------------------------+
      /                                         /
     +-----------------------------------------+
                        |
                        | GPU Vertex Displacement: Delta Y = -(K_z * d_z^2 + K_x * d_x^2)
                        v
                 Curved World Output
                   +---------------+
                  /                 \
                 /                   \
                +                     +
```

### 1.2 Analytical Normal Recalculation

Displacing vertex positions without updating vertex normals causes incorrect lighting calculations (specular highlights and diffuse shading skewing). For a surface defined parametrically by $y(x, z) = y_0 - K_z (z - z_c)^2 - K_x (x - x_c)^2$, we compute the new surface tangent vectors using partial derivatives.

Let the original world normal be $\mathbf{N}_{ws} = (n_x, n_y, n_z)^T$. The gradient of the displacement field $h(x, z) = -(K_x (x - x_c)^2 + K_z (z - z_c)^2)$ is:
$$\frac{\partial h}{\partial x} = -2 K_x d_x$$
$$\frac{\partial h}{\partial z} = -2 K_z d_z$$

The modified world tangent vectors $\mathbf{T}'_x$ and $\mathbf{T}'_z$ along the $X$ and $Z$ axes are:
$$\mathbf{T}'_x = \begin{pmatrix} 1 \\ -2 K_x d_x \\ 0 \end{pmatrix}, \quad \mathbf{T}'_z = \begin{pmatrix} 0 \\ -2 K_z d_z \\ 1 \end{pmatrix}$$

The unnormalized surface normal $\mathbf{N}'_{surf}$ generated by the bending deformation is:
$$\mathbf{N}'_{surf} = \mathbf{T}'_x \times \mathbf{T}'_z = \begin{pmatrix} 2 K_x d_x \\ 1 \\ 2 K_z d_z \end{pmatrix}$$

To blend this macro-surface curvature normal with the mesh's original local normal $\mathbf{N}_{ws}$, we transform $\mathbf{N}_{ws}$ using the Jacobian matrix $J$ of the transformation:
$$J = \begin{pmatrix} 1 & 0 & 0 \\ -2 K_x d_x & 1 & -2 K_z d_z \\ 0 & 0 & 1 \end{pmatrix}$$

The transformed normal vector $\mathbf{N}'_{ws}$ before normalization is calculated via the inverse transpose of $J$:
$$(J^{-1})^T = \begin{pmatrix} 1 & 2 K_x d_x & 0 \\ 0 & 1 & 0 \\ 0 & 2 K_z d_z & 1 \end{pmatrix}$$

$$\mathbf{N}'_{ws} = \text{normalize}\left( \begin{pmatrix} n_x + 2 K_x d_x n_y \\ n_y \\ n_z + 2 K_z d_z n_y \end{pmatrix} \right)$$

### 1.3 SRP Batcher Compatibility Requirements

To keep the **SRP Batcher** active across all objects sharing the curved world shader:
1. All material properties must be declared inside a unified `CBUFFER_START(UnityPerMaterial)` block.
2. No per-frame shader properties may be updated via direct `Material.SetVector()` calls if they vary per object; global curvature settings must be declared in `CBUFFER_START(UnityPerFrame)` or global shader variables set once per frame via `Shader.SetGlobalVector()`.
3. Standard vertex inputs (`Attributes`) and uniforms must match standard URP layout rules.

### 1.4 Production-Ready HLSL Library: `CurvedWorld.hlsl`

```hlsl
#ifndef URP_CURVED_WORLD_INCLUDED
#define URP_CURVED_WORLD_INCLUDED

#include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl"

// Global CBUFFER for frame-wide curvature parameters (SRP Batcher Friendly)
CBUFFER_START(CurvedWorldFrameParams)
    float4 _CurvatureParams; // x: K_x (Lateral), y: K_z (Longitudinal), z: Scale Factor, w: Unused
    float4 _CurvatureAnchorWS; // xyz: World space anchor position, w: 1 = Camera Anchor, 0 = Fixed World Anchor
CBUFFER_END

// Function: Computes 2-Axis Quadratic Displacement
inline float3 ApplyCurvatureDisplacement(float3 positionWS)
{
    float3 anchor = (_CurvatureAnchorWS.w > 0.5) ? _WorldSpaceCameraPos.xyz : _CurvatureAnchorWS.xyz;
    float2 dist = positionWS.xz - anchor.xz;
    
    // Delta Y = -(K_x * dx^2 + K_z * dz^2)
    float deltaY = -(_CurvatureParams.x * dist.x * dist.x + _CurvatureParams.y * dist.y * dist.y);
    
    positionWS.y += deltaY;
    return positionWS;
}

// Function: Computes Curved Position and Adjusted Normal Vector
inline void ApplyCurvatureAndNormal(inout float3 positionWS, inout float3 normalWS)
{
    float3 anchor = (_CurvatureAnchorWS.w > 0.5) ? _WorldSpaceCameraPos.xyz : _CurvatureAnchorWS.xyz;
    float2 dist = positionWS.xz - anchor.xz;
    
    // Displacement
    float deltaY = -(_CurvatureParams.x * dist.x * dist.x + _CurvatureParams.y * dist.y * dist.y);
    positionWS.y += deltaY;
    
    // Analytical Normal Adjustment via Jacobian Inverse Transpose
    float2 grad = float2(2.0 * _CurvatureParams.x * dist.x, 2.0 * _CurvatureParams.y * dist.y);
    float3 adjustedNormal = float3(
        normalWS.x + grad.x * normalWS.y,
        normalWS.y,
        normalWS.z + grad.y * normalWS.y
    );
    
    normalWS = SafeNormalize(adjustedNormal);
}

#endif // URP_CURVED_WORLD_INCLUDED
```

## 2. Parity Between ForwardLit and ShadowCaster Passes

### 2.1 The Shadow Detachment Problem

A primary point of failure in curved world implementations is **shadow detachment** or missing shadows.

```
       Visual Geometry (Curved)           Shadow Map Rendering (Uncurved)
          \                                    /
           \---> [ Displaced GPU Mesh ]       /---> [ Original Mesh Pos ]
                      |                                   |
                      v                                   v
             Renders correctly on screen          Casts shadow at wrong position!
```

When Unity builds shadow maps during the `ShadowCaster` pass:
1. The render pipeline executes a separate vertex shader pass with light projection matrices.
2. If the `ShadowCaster` vertex shader evaluates standard `TransformObjectToWorld()` without applying identical curvature displacement, the shadow map is rendered using unbent mesh coordinates.
3. Shadows cast onto or from curved surfaces detach, floating in air or sinking into ground geometry.

### 2.2 Camera-Centric vs. Fixed World-Origin Anchoring in Shadow Passes

When using camera-relative curvature ($\text{Anchor} = \mathbf{P}_{\text{camera}}$):
- The `ForwardLit` pass renders from the **Main Camera** perspective ($\mathbf{P}_{\text{camera}}$).
- The `ShadowCaster` pass renders from the **Directional Light Camera** or **Cascaded Shadow Camera** perspective.
- **Critical Pitfall**: If `_WorldSpaceCameraPos` is used directly in `ShadowCaster`, Unity evaluates distance relative to the *Light Camera*, resulting in mismatched curvature between geometry and shadow cascades.
- **Solution**: The shader must reference the **Main Camera's World Position** or a **Fixed World Pivot** across all passes.

### 2.3 HLSL ShadowCaster Pass Implementation

Below is a complete, production-grade URP `ShadowCaster` pass compatible with URP 14+ / 17+ (Unity 2022.3 / 2023.3 / Unity 6).

```hlsl
Pass
{
    Name "ShadowCaster"
    Tags { "LightMode" = "ShadowCaster" }

    ZWrite On
    ZTest LEqual
    ColorMask 0
    Cull Back

    HLSLPROGRAM
    #pragma vertex ShadowPassVertex
    #pragma fragment ShadowPassFragment

    // URP Keywords for Shadow Caster
    #pragma multi_compile_instancing
    #pragma multi_compile _ DOTS_INSTANCING_ON
    #pragma shader_feature_local_fragment _ALPHATEST_ON

    #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl"
    #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Lighting.hlsl"
    #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Shadows.hlsl"
    #include "CurvedWorld.hlsl"

    struct Attributes
    {
        float4 positionOS   : POSITION;
        float3 normalOS     : NORMAL;
        float2 texcoord     : TEXCOORD0;
        UNITY_VERTEX_INPUT_INSTANCE_ID
    };

    struct Varyings
    {
        float2 uv           : TEXCOORD0;
        float4 positionCS   : SV_POSITION;
        UNITY_VERTEX_INPUT_INSTANCE_ID
    };

    float3 _LightDirection;
    float3 _LightPosition;

    float4 GetShadowPositionHClip(Attributes input)
    {
        float3 positionWS = TransformObjectToWorld(input.positionOS.xyz);
        float3 normalWS = TransformObjectToWorldNormal(input.normalOS);

        // Apply Curved World Displacement (Exact parity with ForwardLit pass)
        ApplyCurvatureAndNormal(positionWS, normalWS);

        // Standard URP Shadow Bias & Pancaking Logic
        float4 positionCS = TransformWorldToHClip(ApplyShadowBias(positionWS, normalWS, _LightDirection));

        #if UNITY_REVERSED_Z
            positionCS.z = min(positionCS.z, UNITY_NEAR_CLIP_VALUE);
        #else
            positionCS.z = max(positionCS.z, UNITY_NEAR_CLIP_VALUE);
        #endif

        return positionCS;
    }

    Varyings ShadowPassVertex(Attributes input)
    {
        Varyings output;
        UNITY_SETUP_INSTANCE_ID(input);
        UNITY_TRANSFER_INSTANCE_ID(input, output);

        output.uv = input.texcoord;
        output.positionCS = GetShadowPositionHClip(input);
        return output;
    }

    half4 ShadowPassFragment(Varyings input) : SV_TARGET
    {
        UNITY_SETUP_INSTANCE_ID(input);
        #if defined(_ALPHATEST_ON)
            // Alpha clipping logic if using cutout shaders
            half alpha = SampleSampleTexture(input.uv).a;
            clip(alpha - _Cutoff);
        #endif
        return 0;
    }
    ENDHLSL
}
```

### 2.4 Shadow Bias, Pancaking & Cascade Tuning Rules

1. **Shadow Pancaking**: URP clamps vertices outside the shadow light frustum near-plane to the near-plane. Curved shaders that displace geometry downwards can cause geometry to cross the shadow near-plane unexpectedly. Increase `Shadow Near Plane Offset` in URP Asset settings (e.g., from `0.2` to `2.0` - `5.0`).
2. **Depth Bias / Slope Bias**: Because curvature changes surface sloped angles relative to light directions, increase `Depth Bias` slightly (e.g., `0.5` - `1.0`) and `Normal Bias` (`0.75` - `1.2`) on Directional Lights to eliminate shadow acne along bent terrain slopes.

## 3. CPU AABB Frustum Culling & Bounds Expansion (`localBounds`)

### 3.1 Root Cause of Bounding Box Culling Failure

Unity performs CPU-side frustum culling using Axis-Aligned Bounding Boxes (AABBs) computed from unbent object space geometry (`Mesh.bounds` transformed to world space `Renderer.bounds`).

```
                Actual Bent Mesh (GPU)
             \                          /
              v                        v
       [=== Vertex ================== Vertex ===]
       |                                        |
       |     Original CPU Bounding Box          |  <-- Frustum Culling test uses THIS!
       |     +-------------------------+        |      If camera looks down, CPU thinks
       |     |  Unbent Mesh (Original) |        |      box is offscreen -> MESH DISAPPEARS!
       |     +-------------------------+        |
```

When GPU vertex shaders displace geometry downwards by $\Delta y = -(K_z d_z^2 + K_x d_x^2)$, the visual geometry moves outside the static CPU bounding box. If the CPU camera frustum no longer intersects the original unbent bounding box, Unity's C++ rendering engine culls the object, causing instant visual popping/disappearance even while the bent mesh should remain visible in view.

### 3.2 Derivation of Maximum Displacement Bound Estimation

To prevent frustum culling failure, we must expand `Mesh.bounds` (or `Renderer.localBounds`) on the CPU such that the expanded AABB strictly encloses all possible GPU vertex positions under maximum curvature.

Let $B_{\text{local}} = [\mathbf{P}_{\min}, \mathbf{P}_{\max}]$ be the original local AABB of a mesh.

Let $R_{\text{max}}$ be the maximum operational camera-to-object render distance (e.g., camera far clip plane $D_{\text{far}}$).

The maximum downward vertical displacement $\Delta Y_{\max}$ across the domain is bounded by:
$$\Delta Y_{\max} = K_z \cdot (D_{\text{far}} + r_{\text{mesh}})^2 + K_x \cdot (D_{\text{far}} + r_{\text{mesh}})^2$$

where $r_{\text{mesh}}$ is the bounding sphere radius of the local mesh:
$$r_{\text{mesh}} = \frac{1}{2} \|\mathbf{P}_{\max} - \mathbf{P}_{\min}\|$$

The expanded local bounding box $B'_{\text{local}} = [\mathbf{P}'_{\min}, \mathbf{P}'_{\max}]$ requires vertical bounds expansion down by $\Delta Y_{\max}$ (converted to local scale factor $S_{\text{min}}$):

$$\mathbf{P}'_{\min}.y = \mathbf{P}_{\min}.y - \frac{\Delta Y_{\max}}{\min(S_x, S_y, S_z)}$$
$$\mathbf{P}'_{\max}.y = \mathbf{P}_{\max}.y$$

Expanding horizontal extents ($\mathbf{P}'_{\min}.x, \mathbf{P}'_{\max}.x, \mathbf{P}'_{\min}.z, \mathbf{P}'_{\max}.z$) by a factor derived from maximum lateral bending ensures complete coverage across all viewing angles.

### 3.3 Production C# Component: `CurvedWorldBoundsExpander.cs`

```csharp
using UnityEngine;

namespace UnityExpert.CurvedWorld
{
    [DisallowMultipleComponent]
    [RequireComponent(typeof(Renderer))]
    public class CurvedWorldBoundsExpander : MonoBehaviour
    {
        [Header("Curvature Settings (Must match Shader Global Params)")]
        [SerializeField] private float m_Kx = 0.0001f;
        [SerializeField] private float m_Kz = 0.00025f;
        [SerializeField] private float m_MaxCullingDistance = 150.0f;
        [SerializeField] private bool m_ExpandOnAwake = true;
        [SerializeField] private bool m_UseInstanceMesh = false;

        private Renderer m_Renderer;
        private MeshFilter m_MeshFilter;
        private Bounds m_OriginalLocalBounds;
        private bool m_HasExpanded = false;

        private void Awake()
        {
            m_Renderer = GetComponent<Renderer>();
            m_MeshFilter = GetComponent<MeshFilter>();

            if (m_MeshFilter != null && m_MeshFilter.sharedMesh != null)
            {
                m_OriginalLocalBounds = m_MeshFilter.sharedMesh.bounds;
            }
            else
            {
                m_OriginalLocalBounds = m_Renderer.localBounds;
            }

            if (m_ExpandOnAwake)
            {
                ExpandBounds();
            }
        }

        public void ExpandBounds()
        {
            if (m_HasExpanded) return;

            // Calculate max displacement based on max distance
            float maxDistSq = m_MaxCullingDistance * m_MaxCullingDistance;
            float maxDeltaY = (m_Kx * maxDistSq) + (m_Kz * maxDistSq);

            // Account for lossy scale
            Vector3 lossyScale = transform.lossyScale;
            float minScale = Mathf.Min(Mathf.Abs(lossyScale.x), Mathf.Min(Mathf.Abs(lossyScale.y), Mathf.Abs(lossyScale.z)));
            if (minScale < 0.0001f) minScale = 1.0f;

            float localDeltaY = maxDeltaY / minScale;

            // Compute new expanded bounds
            Bounds expanded = m_OriginalLocalBounds;
            Vector3 min = expanded.min;
            Vector3 max = expanded.max;

            // Expand downward along Y axis
            min.y -= localDeltaY;

            // Expand X and Z slightly to cover lateral displacement rotation offsets
            float lateralMargin = localDeltaY * 0.25f;
            min.x -= lateralMargin;
            max.x += lateralMargin;
            min.z -= lateralMargin;
            max.z += lateralMargin;

            expanded.SetMinMax(min, max);

            // Apply via Renderer.localBounds (Unity 2021.2+) or Mesh.bounds
#if UNITY_2021_2_OR_NEWER
            m_Renderer.localBounds = expanded;
#else
            if (m_MeshFilter != null)
            {
                Mesh targetMesh = m_UseInstanceMesh ? m_MeshFilter.mesh : m_MeshFilter.sharedMesh;
                targetMesh.bounds = expanded;
            }
#endif

            m_HasExpanded = true;
        }

        public void ResetBounds()
        {
            if (!m_HasExpanded) return;

#if UNITY_2021_2_OR_NEWER
            m_Renderer.localBounds = m_OriginalLocalBounds;
#else
            if (m_MeshFilter != null && m_MeshFilter.sharedMesh != null)
            {
                m_MeshFilter.sharedMesh.bounds = m_OriginalLocalBounds;
            }
#endif
            m_HasExpanded = false;
        }
    }
}
```

## 4. Vehicle Headlights & URP Lighting Optimization

### 4.1 Forward+ vs Forward (Per-Object) vs Deferred Paths for Vehicle Headlights

When implementing vehicle headlights in racing or arcade driving games, games often feature dozens of active spotlights (2 per vehicle, plus taillights and street lights). The choice of rendering path dictates performance:

```
+------------------------+------------------------------------+----------------------------------+------------------------------------+
| Feature Metric         | Forward (Per-Object Limits)        | Forward+ (Clustered Lighting)    | Deferred Rendering                 |
+------------------------+------------------------------------+----------------------------------+------------------------------------+
| Max Spotlights / Frame | 8 Additional Lights per Object     | 256-1024 Lights per Frame        | Unlimited (G-Buffer Dependent)     |
| Light Culling Method   | CPU Object Grid Intersections      | GPU Compute / Tile Cluster Grid  | Screen-space Light Volumes         |
| Draw Call Impact       | High (Pass re-renders per light)   | Low (Single Pass for all lights) | Low (Constant geometry cost)       |
| SRP Batcher Support    | Fully Supported                    | Fully Supported                  | Restricted / Broken G-Buffer pass  |
| Memory Bandwidth Cost  | Low                                | Medium                           | High (G-Buffer Bandwidth On Mobile)|
| Target Hardware        | Low-end Mobile (GLES 3.0 / Metal)  | Mid/High Mobile & Console/PC     | High-end Desktop / Console         |
+------------------------+------------------------------------+----------------------------------+------------------------------------+
```

#### Strategic Recommendation for Racing/Curved World Games:
- **Use Forward+ Rendering**: Forward+ calculates a 3D Z-sliced screen tile grid on GPU compute shaders. It supports hundreds of simultaneous vehicle spotlights without breaking SRP batching, while avoiding the heavy G-Buffer memory bandwidth overhead of Deferred shading on mobile GPUs (Tile-Based Deferred Renderers like Apple Silicon & Mali).

### 4.2 Spotlight Cookies, Shadow Casting Limits & Layer Masking

1. **Spotlight Cookies**: Vehicle headlights require sharp beam texturing (asymmetric dip patterns, high-beam vs low-beam gradients).
   - In URP Forward+, spotlight cookies are stored in a **2D Texture Array / Atlas**.
   - Ensure all cookie textures use identical dimensions (e.g., `512x512`, `Compressed RGBA ASTC 6x6` or `BC7`) to enable fast GPU indexing without texture array binding state changes.
2. **Shadow Casting Additional Lights**:
   - Limit real-time shadow-casting spotlights to the **player vehicle only** (maximum 2 shadow-casting additional lights).
   - AI vehicles must use non-shadow-casting spotlights with cookie textures, or light cookies blended with screen-space ambient occlusion (SSAO).
   - Set URP Asset `Additional Lights Shadow Resolution` to `512` or `1024` with a tight shadow distance clamp ($25\text{m} - 40\text{m}$).
3. **Light Layer Masking**:
   - Assign Vehicle Headlights to a dedicated Light Layer (`LightLayer 1: Vehicles`).
   - Use Light Layer Masks on road surface meshes to restrict spotlight evaluation exclusively to ground geometry and obstacles, bypassing distant scenery objects.

### 4.3 SRP Batcher Invariants & Lighting Compatibility

The SRP Batcher eliminates CPU draw call overhead by keeping shader memory allocations persistent in GPU VRAM across frames. To preserve SRP Batching with Curved World shaders and Vehicle Headlights:

1. **Constant Buffer Unification**:
   - Every custom shader must declare all material parameters inside `CBUFFER_START(UnityPerMaterial)` and `CBUFFER_END`.
   - Never declare material properties outside CBUFFERs in HLSL blocks.

```hlsl
// CORRECT: Preserves SRP Batcher
CBUFFER_START(UnityPerMaterial)
    float4 _BaseMap_ST;
    half4  _BaseColor;
    half   _Smoothness;
    half   _Metallic;
CBUFFER_END
```

2. **Per-Object Light Data Buffers**:
   - Under Forward+, URP stores additional light indexes in a global StructuredBuffer (`URP_LIGHT_DATA`). Light evaluations inside the shader do NOT introduce per-object CBUFFER variations, keeping all vehicle meshes completely batchable in a single SRP Batch sequence.

## 5. Complete Integrated HLSL Shader: `URPCurvedWorldLit.shader`

```hlsl
Shader "Custom/URP/CurvedWorldLit"
{
    Properties
    {
        [MainTexture] _BaseMap("Albedo Texture", 2D) = "white" {}
        [MainColor] _BaseColor("Albedo Color", Color) = (1,1,1,1)
        _Metallic("Metallic", Range(0, 1)) = 0.0
        _Smoothness("Smoothness", Range(0, 1)) = 0.5
        _BumpMap("Normal Map", 2D) = "bump" {}
    }

    SubShader
    {
        Tags
        {
            "RenderType" = "Opaque"
            "RenderPipeline" = "UniversalPipeline"
            "UniversalMaterialType" = "Lit"
            "Queue" = "Geometry"
        }

        // ------------------------------------------------------------------
        // 1. FORWARD LIT PASS
        // ------------------------------------------------------------------
        Pass
        {
            Name "ForwardLit"
            Tags { "LightMode" = "UniversalForward" }

            HLSLPROGRAM
            #pragma vertex LitPassVertex
            #pragma fragment LitPassFragment

            // URP Keywords
            #pragma multi_compile _ _MAIN_LIGHT_SHADOWS _MAIN_LIGHT_SHADOWS_CASCADE _MAIN_LIGHT_SHADOWS_SCREEN
            #pragma multi_compile _ _ADDITIONAL_LIGHTS_VERTEX _ADDITIONAL_LIGHTS
            #pragma multi_compile_fragment _ _ADDITIONAL_LIGHT_SHADOWS
            #pragma multi_compile_fragment _ _REFLECTION_PROBE_BLENDING
            #pragma multi_compile_fragment _ _SHADOWS_SOFT
            #pragma multi_compile _ FORWARD_PLUS
            #pragma multi_compile_instancing
            #pragma multi_compile _ DOTS_INSTANCING_ON

            #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl"
            #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Lighting.hlsl"
            #include "CurvedWorld.hlsl"

            struct Attributes
            {
                float4 positionOS   : POSITION;
                float3 normalOS     : NORMAL;
                float4 tangentOS    : TANGENT;
                float2 texcoord     : TEXCOORD0;
                UNITY_VERTEX_INPUT_INSTANCE_ID
            };

            struct Varyings
            {
                float4 positionCS   : SV_POSITION;
                float3 positionWS   : TEXCOORD0;
                float3 normalWS     : TEXCOORD1;
                float2 uv           : TEXCOORD3;
                DECLARE_LIGHTMAP_OR_SHADOW(shadowCoord, 4);
                UNITY_VERTEX_INPUT_INSTANCE_ID
            };

            CBUFFER_START(UnityPerMaterial)
                float4 _BaseMap_ST;
                half4  _BaseColor;
                half   _Metallic;
                half   _Smoothness;
            CBUFFER_END

            TEXTURE2D(_BaseMap);
            SAMPLER(sampler_BaseMap);

            Varyings LitPassVertex(Attributes input)
            {
                Varyings output;
                UNITY_SETUP_INSTANCE_ID(input);
                UNITY_TRANSFER_INSTANCE_ID(input, output);

                float3 posWS = TransformObjectToWorld(input.positionOS.xyz);
                float3 normWS = TransformObjectToWorldNormal(input.normalOS);

                // Apply Curved World displacement & analytical normal adjustment
                ApplyCurvatureAndNormal(posWS, normWS);

                output.positionWS = posWS;
                output.normalWS = normWS;
                output.positionCS = TransformWorldToHClip(posWS);
                output.uv = TRANSFORM_TEX(input.texcoord, _BaseMap);

                OUTPUT_LIGHTMAP_UV(input.staticLightmapUV, unityLightmapST, output.staticLightmapUV);
                OUTPUT_SHADOW_COORDS(output, posWS);

                return output;
            }

            half4 LitPassFragment(Varyings input) : SV_TARGET
            {
                UNITY_SETUP_INSTANCE_ID(input);

                SurfaceData surfaceData;
                surfaceData.albedo = SAMPLE_TEXTURE2D(_BaseMap, sampler_BaseMap, input.uv).rgb * _BaseColor.rgb;
                surfaceData.alpha = 1.0;
                surfaceData.metallic = _Metallic;
                surfaceData.specular = half3(0.0, 0.0, 0.0);
                surfaceData.smoothness = _Smoothness;
                surfaceData.normalTS = half3(0, 0, 1);
                surfaceData.emission = half3(0, 0, 0);
                surfaceData.occlusion = 1.0;

                InputData inputData;
                ZERO_INITIALIZE(InputData, inputData);
                inputData.positionWS = input.positionWS;
                inputData.normalWS = SafeNormalize(input.normalWS);
                inputData.viewDirectionWS = GetWorldSpaceNormalizeViewDir(input.positionWS);
                inputData.shadowCoord = GetShadowCoord(inputData.positionWS, input.positionCS);

                half4 color = UniversalFragmentLit(inputData, surfaceData);
                return color;
            }
            ENDHLSL
        }

        // ------------------------------------------------------------------
        // 2. SHADOW CASTER PASS (Parity guaranteed)
        // ------------------------------------------------------------------
        Pass
        {
            Name "ShadowCaster"
            Tags { "LightMode" = "ShadowCaster" }

            ZWrite On
            ZTest LEqual
            ColorMask 0
            Cull Back

            HLSLPROGRAM
            #pragma vertex ShadowPassVertex
            #pragma fragment ShadowPassFragment

            #pragma multi_compile_instancing
            #pragma multi_compile _ DOTS_INSTANCING_ON

            #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl"
            #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Shadows.hlsl"
            #include "CurvedWorld.hlsl"

            struct Attributes
            {
                float4 positionOS   : POSITION;
                float3 normalOS     : NORMAL;
                UNITY_VERTEX_INPUT_INSTANCE_ID
            };

            struct Varyings
            {
                float4 positionCS   : SV_POSITION;
                UNITY_VERTEX_INPUT_INSTANCE_ID
            };

            float3 _LightDirection;

            Varyings ShadowPassVertex(Attributes input)
            {
                Varyings output;
                UNITY_SETUP_INSTANCE_ID(input);
                UNITY_TRANSFER_INSTANCE_ID(input, output);

                float3 posWS = TransformObjectToWorld(input.positionOS.xyz);
                float3 normWS = TransformObjectToWorldNormal(input.normalOS);

                // Apply Curved World displacement parity
                ApplyCurvatureAndNormal(posWS, normWS);

                float4 posCS = TransformWorldToHClip(ApplyShadowBias(posWS, normWS, _LightDirection));

                #if UNITY_REVERSED_Z
                    posCS.z = min(posCS.z, UNITY_NEAR_CLIP_VALUE);
                #else
                    posCS.z = max(posCS.z, UNITY_NEAR_CLIP_VALUE);
                #endif

                output.positionCS = posCS;
                return output;
            }

            half4 ShadowPassFragment(Varyings input) : SV_TARGET
            {
                return 0;
            }
            ENDHLSL
        }
```
